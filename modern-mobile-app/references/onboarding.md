# Onboarding Patterns (reference)

Source: Mobbin, "I Studied 1,460 Onboarding Flows. Here's What I Found." (986 apps, 1,460 flows).
Core thesis: **screen count is the wrong metric.** Onboarding averages 25 screens but ranges from 3 to 187 — and the long flows work because every screen visibly builds toward a personalized outcome. "Users don't mind length; they mind friction without payoff. A form feels long; a conversation doesn't."

## Patterns that work

- **Show the outcome, not features.** Opening screens depict the end state the user wants (Arc, Spotify, Strava, Instagram, Airbnb, Pinterest, Tinder, Facebook, Timehop) instead of listing capabilities.
- **Feels-human touches.** Small, non-functional moments users remember and forgive: BitePal asks you to name a raccoon midway through a 61-screen flow.
- **Personalization — then outcomes.** Only 23.4% of apps personalize. Four recurring question types: motivations (Calm), usage (Lose It!), attributes (Brilliant), knowledge (Radicle, Agora). Feed answers back into a tailored end-state preview (Arc, Strava, Spotify).
- **Personalize before monetizing.** 217 apps paywall during onboarding; 71% ask for money without asking anything about the user first. Only ~6% personalize-then-paywall — and those run the longest flows (42 screens avg.). The winning sequence: ask, visibly build something from the answers, show it, then price it. Noom ($209/yr) projects weight loss on a graph with the user's name; Lemonade runs 143 screens via chatbot "Maya" ending in a quote.
- **Make long flows feel short.** Five recurring devices: an early progress bar, personal questions, a "mirror" reflecting the user back (Noom labels you "Structure Seeker"), a taste of the product before the paywall (Duolingo's first lesson by screen 12, Headspace's 20-second breath, Hinge has you writing profile prompts by screen 15), and a plan built from your answers.
- **Teach in context.** Replace tutorial screens (only 7.9% of apps) with doing the real thing early — Duolingo starts lessons within its 76 screens; Headspace opens with "Breathe in."
- **Ask at the right moment.** Time sensitive asks (permissions, notifications, payments) for when their need is obvious — never front-loaded.
- **Skip when the user knows the task.** Midjourney (3 screens) and Noom (113) are both right: no onboarding when the user already knows what they came for.

## Rules of thumb

- Tone is set by screen 2–3 and almost never revised; by screen five the user knows whether the app was built for them.
- Progress bar appears on screen 2–3 and never leaves — a promise there is an end.
- One question per screen; prefer low-effort inputs (agree-sliders over open-ended text).
- Reflect answers back as an identity label ("Structure Seeker," "Careful Beginner") — horoscope-like precision users love.
- Category norms differ wildly: Finance ~40 screens, Health & Fitness ~36, Maps & Nav ~13; AI apps converged on 10–25 ("get to value fast"). Web flows run ~21% shorter than iOS.

## Warnings

- Correlation is not causation: the data shows what flows look like, not what performs. Copying a pattern won't copy the result.
- Hidden paywalls backfire: a quiz that never mentions a price, then demands one, reads as manipulative — disclose what's coming.
- Don't paywall before you've earned it (the 71% mistake).
- The "best onboarding is a skip button" meme is only right when the user knows the task; when the app must know the user, skipping defeats the product.
- Delightful touches get flagged in review as "scope creep" — yet they're the most memorable part of a 61-screen flow.
